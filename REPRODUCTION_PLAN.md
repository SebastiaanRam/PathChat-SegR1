# Plan: Reproduce a Usable PathChat-SegR1 on Public Data (1× H200)

## Context

**Paper:** PathChat-SegR1 (ICLR 2026). Reasoning-segmentation for pathology. Architecture = Qwen2.5-VL backbone + RuiPath pathology vision encoder + MedSAM image encoder + adapter → SAM mask decoder. Trained in 3 stages (pretrain → SFT → SO-GRPO). Built a 118,667-triplet benchmark; reports +61% Dice over MMR-7B on out-of-domain pathologies.

**What's actually shipped in the repo we have:**
- Source code with several **critical gaps**: `extract_mask_from_response` returns *random* masks (`utils/reward_model.py:201-247`); `extract_stain_vectors` returns random tensors (`utils/vision_encoders.py:217-222`); SO-GRPO loss combines reward terms with **flipped signs** so reward maximization becomes minimization (`utils/so_grpo_trainer.py:98-109`); inference-time mask generation is incomplete (`model/QWSA.py` only fully runs the mask decoder in *training* mode using ground-truth masks).
- `model/QWSA.py:151-249` forward pass **is** complete for SFT.
- `utils/randstainna.py` and SO-GRPO algorithmic skeleton (GAE, soft-Dice reward) **are** complete.

**What's blocking faithful reproduction:**
- **No released weights.** README points to `github.com/Misterursw/pathchat-seg` (404). Paper points to `github.com/yul945562-bit/Pathseg` which contains only this same zip.
- **`paige-ai/RuiPath` HF ID returns 401**; not publicly available.
- **Private datasets unavailable**: 43,847 frozen-section images + 25,764 PMBT + 13,847 RD are from Shanghai Ruijin Hospital and not released.
- **Reasoning-chain labels** were generated by Gemini-2.5-Pro + DeepSeek-R1 + 3 pathologist reviewers — not redistributed.

**User's scope (confirmed):**
- Hardware: **1× NVIDIA H200 (141 GB HBM3e)**.
- Datasets: **GlaS + CRAG + DigestPath only** (~10s of GB, fast iteration).
- Reasoning chains: **generate locally** with a Qwen2.5-VL model.
- Vision tower: **skip RuiPath**, use Qwen2.5-VL's native ViT.
- Stages: **SFT + SO-GRPO with bug fixes**.

**Intended outcome:** a working reasoning-segmentation model trained end-to-end on three public datasets, evaluated zero-shot on a held-out split. Quality will trail the paper (no RuiPath, no private data, smaller training set, ~7B not the implicit larger backbone) but the pipeline will be real and the bugs fixed.

## Architecture decisions

1. **Backbone:** `Qwen/Qwen2.5-VL-7B-Instruct` (paper used 3B, but 7B is the public default and fits comfortably in 141 GB with LoRA). Set via `--model_name_or_path`.
2. **Vision tower:** Native Qwen2.5-VL ViT. Disable `--use_ruipath_encoder`. (Confirmed gated/missing.)
3. **Segmentation backbone:** `MedSAM ViT-B` from MedSAM repo (`medsam_vit_b.pth`). Code uses `build_sam_vit_b()` at `model/QWSA.py:114`. Public download: `https://github.com/bowang-lab/MedSAM` checkpoint release.
4. **Reasoning-label generator:** `Qwen/Qwen2.5-VL-32B-Instruct-AWQ` (≈22 GB, fits beside training). Used offline once to label the dataset; not in the training graph.
5. **Stain-invariant pretraining of MedSAM encoder:** **skip for first run**; `extract_stain_vectors` is a stub. Re-introduce only if first run underperforms.

## Files to touch (with exact reasons)

### A. Bug fixes (must-do before any RL)

- `utils/so_grpo_trainer.py:98-109` — **flip the sign** of `lambda_soft / lambda_sparse / lambda_spatial / lambda_format` reward terms in `total_loss` (rewards subtract, penalties add). Without this, SO-GRPO drives Dice **down**.
- `utils/reward_model.py:201-247` — replace `extract_mask_from_response` (currently returns random masks) with a real implementation: locate the `<SEG>` token positions in the generated sequence, re-run the model with `output_hidden_states=True`, push the SEG hidden state through `model.text_hidden_fcs`, and call SAM prompt-encoder + mask-decoder. Pattern to follow is already correct in training forward at `model/QWSA.py:184-221` — extract that into a shared helper.
- `model/QWSA.py` — add a `generate_with_mask()` method mirroring the training mask-decoder path so `test.py` can produce masks at inference. Currently `test.py:47-177` walks tokens looking for `"seg"` substrings, which is brittle; use the `seg_token_idx` token id instead.
- `utils/vision_encoders.py:217-222` — `extract_stain_vectors` returns random tensors. Either implement the [A_v, D_v] LAB-channel mean/STD extraction the paper describes (Eq. 1, two augmented views) or **disable** the term by setting `--stain_distillation_weight 0` and skipping `--use_stain_distillation`. Recommend the latter for first run.

### B. Configuration

- `training/finetune/run_finetune.sh` — single-GPU launcher (replace `deepspeed --include localhost:0,1,2,3` with `localhost:0`). Set `BATCH=2`, `GRAD_ACC=16`, `LR=3e-5`, `LORA_R=16`, `LORA_ALPHA=32`, `EPOCHS=3` for first run.
- `training/so_grpo/run_so_grpo.sh` — same single-GPU shape; `LR=1e-6`.
- `training/shared/config_manager.py:88-94, 96-100` — DeepSpeed configs default to ZeRO-3 (pretrain) / ZeRO-2 (SFT). On 1×H200 we don't need ZeRO; pass a custom config with `stage: 0` (or `--deepspeed_config none`) to avoid CPU offload overhead.

### C. New scripts

- `psydata/build_public_dataset.py` (new) — converts GlaS/CRAG/DigestPath to the JSON+polygon format `utils/data_processing.py:9-60` expects:
  - For each image, derive polygon contours from the binary GT mask via `cv2.findContours`, write to `<name>.json` with the `shapes[].points` schema documented in `psydata/outputfolder_to_formatjson.py:37-56`.
  - Emit a top-level `train.json` array of `{query, outputs, image, json}` rows (schema from `psydata/generate_final.py:47-52`).
  - Pull queries from `utils/prompt_info.py` (already has multiple variants).
  - Leave `outputs` empty for now — filled by step D.
- `psydata/generate_reasoning_chains.py` (new) — runs `Qwen2.5-VL-32B-Instruct-AWQ` over the dataset to populate the `outputs` field. Prompt template: feed the image + GT mask (overlaid) + dataset-specific clinical context (gland morphology for GlaS/CRAG, lesion morphology for DigestPath) and ask for a structured reasoning trace ending in `<SEG>`. Mirror the style in `example/example1/ex1.json`.

### D. Evaluation

- `eval/evaluate_dice.py` (new) — held-out split evaluator. Loads `test.py`'s inference path, runs over the val split, computes Dice/IoU per dataset. Reuse `test.py:47-177` structure.

## Verification

1. **Pipeline smoke test (step 4):** `python test.py --model-path Qwen/Qwen2.5-VL-7B-Instruct --image-path dataset/public/val/glas_001.png --prompt "Segment the glandular regions." --sam-checkpoint medsam_vit_b.pth --out-dir /tmp/smoke` should output a non-empty mask PNG and a printed reasoning string. If the printed text is non-empty but the mask is all-zero, the bug-fix in A3 is incomplete.
2. **SFT convergence (step 6):** training loss should drop monotonically; mean batch Dice in logs should rise above 0.4 within the first epoch on GlaS. If not, inspect `<SEG>` token id alignment (`tokenizer.convert_tokens_to_ids("<SEG>")` must match `seg_token_idx` passed into the model).
3. **SO-GRPO sanity (step 8):** mean reward per step in TensorBoard should monotonically increase. If it monotonically *decreases*, the loss-sign fix (A1) wasn't applied. Validate by running `pytest -k so_grpo` (write a small unit test asserting `total_loss` decreases when soft_reward is replaced with a constant 1.0).
4. **End-to-end Dice (step 9):** target ≥0.7 on GlaS held-out (paper reports 0.87 on full system). Anything significantly below 0.5 means LoRA isn't reaching the SAM mask decoder — check that mask decoder gradients are actually flowing (`p.requires_grad` on `visual_model.mask_decoder` parameters).

## What this plan deliberately does *not* attempt

- RuiPath substitution (UNI2 / Virchow). Both are gated; defer to a v2 if results are weak.
- Private dataset replication. Not feasible.
- Stain-invariant self-distillation pretraining. The stub at `utils/vision_encoders.py:222` makes this nontrivial; it's an ablation worth +0.07 Dice in the paper but adds days.
- Full reasoning-chain quality matching the paper's Gemini+DeepSeek+3-expert pipeline. Local Qwen-32B-AWQ is the agreed compromise.
- Reproducing the 61% out-of-domain improvement number — that requires the private PMBT/RD test sets.
